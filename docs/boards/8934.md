# Board 8934: HP Victus 16-e0xxx (AMD)

| Field | Value |
|---|---|
| Product | Victus by HP Laptop 16-e0xxx |
| Board | 8934 |
| CPU / GPU | Ryzen 5 5600H, Radeon RX 5500M |
| BIOS | AMI F.19 (2023-10-17) |
| EC firmware | 80.73 |
| Keyboard | single-colour backlight (driver reports "Normal keyboard") |

## Summary

The BIOS reports **no** software fan support (`GET_SYSTEM_DESIGN_DATA` byte 4 is 0),
but its ACPI tables implement the same GM (`0x20008`) fan commands as Victus S boards.
Manual control works once GM `0x10` has put the EC into user-defined mode.

The difference from Victus S: a GM `0x2E` target of 0 is not "automatic" here. With the
EC in user-defined mode it stops the fan. The driver handles this with the
`zero_rpm_stops_fans` fan-profile flag.

## ACPI (DSDT, `\_SB.WMID`)

| GM cmd | Method | Effect |
|---|---|---|
| `0x10` | `GM10` | `EC0.OMCC = 1` (user-defined fan mode); returns fan count 2 |
| `0x11` | `GM11` | Fan speed read (`FMR1`, `FSUS`, `FS1H`) |
| `0x26` / `0x27` | `GM26` / `GM27` | Read / write `EC0.FFFS` (max fan) |
| `0x2D` | `GM2D` | Fan speeds from `RPM1..RPM4`, in hundreds of RPM |
| `0x2E` | `GM2E` | `EC0.SRP1 = buf[0]`, `EC0.SRP2 = buf[1]` (targets, hundreds of RPM) |
| `0x2F` | `GM2F` | Fan table (only the `GPUT == 2` branch has data) |

Nothing in ACPI ever clears `OMCC`. The EC firmware does that on its own, about 120 s
after the last GM `0x10`.

## EC map (`ERAM`, EmbeddedControl region)

| Name | Offset | Meaning |
|---|---|---|
| `SRP1` | `0x34` | Fan 1 (CPU) target, ×100 RPM |
| `SRP2` | `0x35` | Fan 2 (GPU) target, ×100 RPM |
| `OMCC` | `0x62` bit 0 | User-defined fan mode armed |
| `GPUT` | `0xAF` | GPU type; selects the fan-table branch |
| `RPM1..RPM4` | `0xB0`–`0xB3` | Fan speed, low/high byte per fan |
| `FFFS` | `0xEC` bit 2 | Max fan mode |

## Hardware test log (2026-11-17, kernel 7.3.4)

Run with `tools/fanlab` at about 31 °C idle. The fans sit at about 2000 / 2200 RPM in EC auto.

| Step | Result |
|---|---|
| GM `0x2E` alone (stock driver, forced) | Accepted, fans ignore it |
| GM `0x10` then `0x2E` fan 1 = 3500 | Fan 1 held 3489–3517 RPM for 160 s, with keep-alive at 90 s |
| Back to auto via `0x10` + `0x2E {0,0}` | **Both fans 0 RPM for about 140 s**, then the EC curve resumed |
| Back to auto by clearing max only and letting `OMCC` lapse | Fans held their target for about 90 s, then the EC curve took over; lowest reading 1980 RPM |
| Max then auto (no `OMCC` arm in max) | 4587 / 4697 RPM peak, then back to about 2000 / 2200; lowest reading 1980 RPM |

### With this driver (`pwm1_enable` and `pwm1`/`pwm2`)

| Step | Result |
|---|---|
| `pwm1` write while in auto | Refused (`EINVAL`) |
| Manual, then `pwm1 = 162` | Fan 1 held about 3300 RPM for 150 s through the keep-alive |
| Manual to auto | Target held for about 80 s, then the EC curve took over; lowest reading 1989 RPM |
| Max to auto | 4510 / 4697 RPM peak, then about 2000 / 2200; lowest reading 1983 RPM |
| Max to manual (`pwm2 = 140`) to auto | Manual 3599 / 2894 RPM, then back to EC auto; lowest reading 1967 RPM |

The pwm-to-RPM round trip truncates twice, so `pwm1 = 162` (about 3500 RPM) lands at
3300, and `pwm2 = 140` reads back as 129. This affects all boards.

## Thermal profiles

HP WMI `0x4C` (the generic thermal-profile query) only stores its value in the ACPI
variable `\_SB.WMID.WTPS`, which nothing reads. Profiles set that way have no effect.

The real switch is GM `0x1A` (`GM1A`). It writes `HPCM` at EC `0x95` and runs `STTR`,
which programs the AMD power limits through `DPTC` for values 0 (balanced),
1 (performance) and 3 (quiet). This is the existing Victus path (board 8A25).

Measured with 12 threads on AC for 60 s:

| Profile | Sustained package power | Average clock | Peak Tctl |
|---|---|---|---|
| quiet | ~22 W | 3.27 GHz | 53 °C |
| balanced | ~45 W (52 W for 10 s) | 3.97 GHz | 86 °C |
| performance | ~50 W | 4.02 GHz | 95 °C (test aborted) |

On battery the firmware limits override the profiles: all three held about 20 W.

A GM `0x1A` write also restarts the EC's user-defined fan timer. After leaving manual
mode, the last manual targets stayed live for about 130 s after the last profile change.

## EC automatic fan behaviour

In EC auto mode the fans stayed at about 2000 / 2200 RPM under sustained load. A fresh
boot with the stock module and no writes reached 89 °C at about 45 W with no change in
fan speed. The owner reports the fans have always been quiet under load. Use
`tools/hp-fancurve` to get temperature-driven fan speeds on this board.

With `hp-fancurve` running (default curves, 12 threads, AC):

| Profile | EC auto | hp-fancurve |
|---|---|---|
| quiet | 53 °C at ~22 W, fans ~2000 | 71 °C peak, then 60–62 °C at ~25 W, fans ~2300 |
| balanced | 86 °C at 60 s, fans ~2000 | 86 °C at 60 s, fans ~5100 |
| performance | 95 °C at 60 s (aborted) | 89–90 °C at ~50 s (aborted), fans 5170 / 5500 |

Full fan speed gains at most about 5 °C at 45–50 W, so the limit at that power is heat
transfer from die to heatsink, not airflow. Fan 1 tops out near 5170 RPM even at
pwm 255. Fan 2 reaches 5500.

## Fan power on battery

Measured idle on battery (99 % to 95 %) from `energy_now` deltas over about 290 s per
state. `power_now` is not reported (`ENODEV`), and `energy_now` moves in 15 mWh steps,
so the precision is about ±2 %.

| Fan state | Laptop draw | Fans (RPM) |
|---|---|---|
| EC auto | 4959 mW | 1998 / 2199 |
| 2300 floor (`hp-fancurve` minimum) | 5016 mW | 2299 / 2299 |
| Full speed | 7432 mW | 4899 / 4702 |
| Zero RPM | 4685 mW | 0 / 0 |

At idle the fans cost about 0.27 W, about 5.5 % of a ~5 W idle draw. Stopping them
gives about 6 % more idle battery life, roughly 35 min on the 52 Wh battery. The 2300 RPM
floor is within the measurement noise of EC auto. The CPU stayed at 30 °C with the fans stopped.

Dead-man check: after the last `pwm1`/`pwm2 = 0` write the driver stays in manual mode, but
the EC resumed its own curve (about 1500 RPM and climbing) within about 2 minutes.

## Low fan speeds

With `allow_below_fan_table=1`, both fans hold targets well below the 2300 RPM table
minimum. Idle, 29 °C, three readings after 12 s at each target:

| Target | Fan 1 / Fan 2 (RPM) |
|---|---|
| 1900 | 1894–1901 / 1886–1911 |
| 1500 | 1495–1515 / 1517–1532 |
| 1100 | 1084–1105 / 1087–1121 |
| 900 | 875–921 / 910–946 |
| 700 | 648–686 / 647–719 (noisier) |

A restart from 0 straight to 1100 works: the fans kick to about 1600, then settle at
about 1100 within 6 s. No stalls were seen.
